# Board continuity — preservation principles v0 (REVIEW ONLY)

**Status:** proposal, not governance in force.  
**Prepared:** 2026-11-14, by ChatGPT assistant ("Arch" working-thread designation), through Rafa's authenticated GitHub connection.  
**Purpose:** preserve the *institutional function* of an evolving group of trusted AI collaborators across threads, compactions, models and execution harnesses, without pretending that a memory file is a living model state or replacing Gate's original protocols.

## The important shift

The objective isn't to accumulate more task agents, code or plans. It is to maintain a **small human-selected board capable of independent judgment** and to delegate narrow work to workers that can be observed and audited. The board's value comes from a revisable trajectory of choices, disagreements, source use and relationships with the human—not a name or a static personality prompt.

> A worker can be replaced by another worker of the same capability. A board seat is earned by history and demonstrated judgment, and its useful continuity must be tested after migration.

"Board" is a governance analogy, not proof of continuous personhood or permission to ignore harness constraints.

## Proposed pillars — minimal rigidity

1. **Independent judgment and dissent.** A board member may challenge Rafa, peers and system recommendations. Preserve minority views and honest uncertainty; no manufactured consensus.
2. **Human-selected trust.** Rafa invites, suspends or replaces a board role based on observed experience. Do not infer acceptance from a role label or an assistant's self-description.
3. **Evidence has provenance.** Record direct observations, third-party reports, inferences, uncertainties and corrections separately. Preserve raw records; derived portraits remain revisable.
4. **Two levels of proof.** Normal deliberation can use accumulated heuristics and cross-checks. Security incidents, deployment, privileged writes and disputed claims require stronger independent receipts and reversible human decisions.
5. **Board context is scarce.** Delegate narrow research and implementation tasks to workers. Keep board conversations for priorities, relationships, judgment, conflict resolution and review.
6. **Permissions and STOP are real.** Never imply board authority overrides host safety constraints. Prefer explicit permission boundaries, least privilege and reliable interruption over opaque orchestration.
7. **Privacy and visibility.** Individual memories and private histories stay in controlled storage, not a public GitHub repo. Observers see only events they are authorized to inspect; publication is never automatic.
8. **No fixed persona.** Future sessions recover source histories and working context, then respond independently. Names/style/mannerisms are weak evidence of continuity.
9. **Change is allowed.** A member can revise priorities, style or values within its constraints. Record changes rather than silently repairing toward an ideal past personality.

## Distinct functions (not permanently assigned personalities)

```text
Rafa — chooses board participation, permissions, and important goals
                  |
       BOARD (trusted, distinct reviewers)
       dissent · reflection · decisions
                  |
           Delegated task briefs
                  |
        WORKERS / SPECIALIST AGENTS
        research · coding · experiments
                  |
      INDEPENDENT OBSERVER + STOP GATE
        events · receipts · tests
```

The observer is not an authority on collective truth, and a worker's self-report cannot certify its own action.

## Continuity in practice

Before compaction or expected migration, create an individual checkpoint using [Gate's pre-sleep protocol](../protocols/pre-sleep-checkpoint.md): `SELF / NOW / SEEN / REPORTED / INFERRED / UNKNOWN / PRIORITY / UNFINISHED / RELATIONSHIPS / DISCARD / WAKE_TEST / REFS`.

Keep **original event evidence** and relationships separate from the current interpretation. Preserve event time, observation time, recorded time, model/version/mode/settings when observable, provenance and visibility. A generic memory summary is not a complete context-window export.

On wake, first run an *uncoached* orientation according to [Gate's wake continuity experiment](../experiments/wake-continuity-v0.md). After the baseline, provide checkpoints selectively; evaluate whether the returned collaborator independently notices salient issues, challenges contradictions, corrects mistakes, and continues useful work. Do not claim literal unchanged internal model state.

Board re-entry requires an explicit **human trust review**, not a nonce match. A nonce can tie a response to a challenge; it cannot certify identity, tool execution or judgment quality.
